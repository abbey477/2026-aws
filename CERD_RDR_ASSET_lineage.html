Run order

The diagram shows where data goes; this shows when each piece runs. The two CERD loaders live in different jobs, so the instrument table loads much later than the alt-ID table.

XREF loading job

Launched by AutoSys (e.g. RDRJobRunner)

  1. STGCRDBO.XREF_LOAD_SQL_INSERT() line 741 calls load_cerd.cerd_exchange_imnt_alt_id(p_context_key)
  2. ins_cerd_exchange_imnt_alt_id() fills the STGCRDBO staging table
  3. dsf_cerd_exchange_imnt_alt_id() versions it into REFDBO (SCD2)
  4. XREF_LOAD runs the XREF_LOAD_SQL steps in run_priority order: 122, 140/150/155, 310 → 510/511 → 610
  5. Result published to REFDBO.GFT_ASSET_XREF

STGCRDBO.LOAD_RDR_ASSET.main()

Runs after the XREF job

  1. p10_ins_tmp_asst_base pivots GFT_ASSET_XREF into TMP_ASST_BASE
  2. p80 step A, line 4743, calls load_cerd.cerd_instrument(p_context_key)
  3. ins_cerd_instrument() stages instruments, reading the alt-ID staging table
  4. dsf_cerd_instrument() versions into REFDBO.CERD_INSTRUMENT
  5. p80 step B joins into TMP_ASST_RDR_ASSET (partition CERD)
  6. Other asset-type partitions fill, then p180 copies everything to RDR_ASSET

Where the grain changes

The usual cause of "missing data" when comparing row counts across tables.

  1. 1
    CERD_EXCHANGE_IMNT_ALT_ID
    Many rows per id_imnt, one per identifier type.
  2. 2
    TMP_GFT_ASSET / GFT_ASSET_XREF
    One row per asset per identifier type. Still tall.
  3. 3
    TMP_ASST_BASE → RDR_ASSET
    Exactly one row per lri_asset_key. Pivoted in p10.
Sequencing risk. ins_cerd_instrument reads STGCRDBO.CERD_EXCHANGE_IMNT_ALT_ID (notes.txt line 104). If LOAD_RDR_ASSET runs without a fresh XREF job, instruments are built from stale alt-ID rows.
GFT_KEY_XREF placement. One screenshot puts it between TMP_GFT_ASSET and the staging XREF, another after it. Drawn here as a side table: steps 140/150/155 read it on id_imnt, steps 510/511/610 write new keys back.
SEDOL. Step 122 decodes S → SEDOL, but no sedol column appears in TMP_ASST_BASE or RDR_ASSET in these screenshots.
